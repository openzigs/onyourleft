# Code of Conduct

## Why this is not the Contributor Covenant

Most projects adopt the [Contributor Covenant](https://www.contributor-covenant.org), and adopting it
here would be reasonable. This is **not** it, and the reason is the same one that governs everything
else in this repository: its canonical text could not be reached from the environment this file was
written in, and reproducing a licensed document from memory is how a subtly wrong version ends up
carrying somebody else's name on it. `LIC005` exists because this project does not do that with
licence texts, and it will not do it with this either.

So what follows is the project's own, in its own words. **Adopting the Contributor Covenant verbatim
remains open**, and it is a small change for whoever has the real text in front of them: replace this
file with it, keep its CC BY 4.0 attribution, and point the reporting section below at the same
place.

## The standard

Be someone other people can work with. Concretely:

- **Argue with the work, not the person.** "This read is unscoped and passes every single-athlete
  test" is a good review. "You clearly did not think about this" is not, and it is not more true for
  being blunter.
- **Say what you actually checked.** This repository asks for a mutation list rather than a coverage
  number because "I ran it and it passed" is not evidence. The same honesty applies to a review: if
  you did not run it, say you did not run it.
- **Take a correction the way you would want one taken.** Being wrong in public is the ordinary cost
  of working in the open. Nobody here needs to perform certainty.
- **Assume the constraints are real until you have read them.** Several things that look like
  oversights are decisions with reasons written down — ANT+, the absence of a server, the metric
  names. Read the reason before proposing the reversal; then propose it if the reason is wrong.

## Not acceptable

Harassment, whether public or private. Sexualised language or imagery. Personal attacks, including
about someone's identity, background, health, or competence. Deliberate misgendering or use of a name
someone has asked you not to use. Publishing anyone's private information — and in this project that
explicitly includes **their location**: a GPS trace shows where somebody lives, and posting one
without consent is doxxing, not a bug report.

Sustained disruption also counts. Reopening a settled decision for the fourth time is not persistence.

## Scope

Issues, pull requests, commit messages, code comments and any space where you are representing this
project.

## Reporting

Report through GitHub, to the repository owner: open a private security advisory at
[the advisory form](https://github.com/openzigs/onyourleft/security/advisories/new), which is the
one private channel this project has. It is labelled for vulnerabilities, and it is the right place
for this too — say at the top that the report is a conduct matter rather than a vulnerability.

⚠️ **Do not open a public issue about someone's conduct.** It is worse for the person reporting and
worse for the person reported, and it cannot be undone.

What to expect: an acknowledgement when it is seen, not within a guaranteed window — the same promise
`SECURITY.md` makes, and for the same reason, which is that this is a small project and a promise
nobody can keep is worse than an honest one.

## Enforcement

The repository owner decides, and the range runs from a private word through to a block. Whoever
decides recuses themselves if the report is about them.

This is a small project run by few people. That is a limitation worth stating plainly rather than
dressing up as a process: there is no committee, and there is no appeal beyond the owner.
